What does it mean to lanuch a program

It turns static code on your disk into an active process in your computers memory

4 steps to lanuching a program

1. Finding and Reading: The OS goes to your disk and locates the executable and reads it header to understand how much memory it needs

2. Allcating Memory: The OS makes room for a brand-new isolated address space in RAM.
                     It sets up boundaries for the programs stack, heap and data segments

3. Loading: The OS copies the compiled machine code from the disk into that newly allcated ram 

4. Executing: The OS sets the CPU program counter to the entry point of the program and hands over control
              now the program is offically running

Difference between child process and parent process

A parent process is an existing process that creates a new process (called a child process)
using a system call like fork(), while a child process is the new subprocess as a copy or derivative of 
that parent.

Differences 

1. Creation and Control: The parent process initates the child process and manages or monitors it's exetion.
                         The child process executes tasks often concurrently with the parent

2. Hierarchy and Quantity: A parent process can have multiple child processes. 
                           However a standard child process has only one parent process.

3. Return values(fork()): When a fork() call succeeds, the parent process receives 
                          the Process ID (PID) of the child, whereas the child process receives 0.

4. Termination Signal: When a child process finshes or exits, it sends a termination signal 
                       (such as SIGCHLD in UNIX-like systems) back to it's parent process.

5. Resources Inheritance: A child process initally iherits a copy of the parent's address space,
                          open files, and envirourment attributes, though they operate in separte memory spaces

Example

#include <iostream>
#include <unistd.h>
#include <sys/types.h>
#include <sys/wait.h>

int main() {
    // Fork the process to create a child process
    pid_t pid = fork();

    if (pid < 0) {
        // Fork failed
        std::cerr << "Fork failed!" << std::endl;
        return 1;
    } 
    else if (pid == 0) {
        // Child process execution
        // fork() returns 0 to the child process
        std::cout << "[Child Process] Hello from the child! My PID is: " << getpid() << std::endl;
        std::cout << "[Child Process] My parent's PID is: " << getppid() << std::endl;
    } 
    else {
        // Parent process execution
        // fork() returns the child's PID to the parent process
        std::cout << "[Parent Process] Hello from the parent! My PID is: " << getpid() << std::endl;
        std::cout << "[Parent Process] I spawned a child with PID: " << pid << std::endl;

        // Wait for the child process to finish before exiting
        wait(nullptr);
        std::cout << "[Parent Process] Child has terminated. Parent exiting." << std::endl;
    }

    return 0;
}

How it works: 

    fork() splitting: The exact moment fork() is called, the OS duplicates the current process.
                      Two identical programs now run from that exact line forward.
    
    The Return Value (pid): The system uses the value of pid to let each process know
                            it's identity. The parent gets the child actual ID numbers
                            while the child gets a flat 0.
    
    wait(nullptr): This keeps the parent process paused until the child process completes its work.
                   This prevents the child from turing into a zombie process (a finshed process 
                   whose exit status hasn't been read by it's parent)


What is a Process ID (PID): is a unique number assinged by an OS kernal to track and maange an 
                            active program or background task.

Unique Identification: When you open an app or service, the OS gives it a specifc number.
                       Even if you run three different windows of the same program,
                       each instance get's it's own PID.

Temporary and Reuseable: A PID lasts only as long as the process is running.
                         Once you close the program, the process ends, and the OS
                         can later reasssing the same number to a new process.

Code example 

#include <iostream>
#include <unistd.h> // Required for POSIX operating systems

int main() {
    // Get the Process ID of the current application
    pid_t pid = getpid();
    
    // Get the Parent Process ID (e.g., the terminal/shell running this program)
    pid_t ppid = getppid();

    std::cout << "Linux/macOS Process ID (PID): " << pid << std::endl;
    std::cout << "Parent Process ID (PPID): " << ppid << std::endl;

    return 0;
}

What does fork() do

fork() creates a brand new process by duplicating the existing one. 

The original process is called the parent process and the new one 
is called the child process. 

When you call fork() the OS makes an exact clone for your program at that
exact line of code. Both processes then continue executing simultaneously
from that same point onwards.

To tell them apart fork() returns different values to each process.

To the parent process: it returns the Process ID (PID) of the child.
To the child process: it returns 0
If it fails: it returns -1 

Code example 

#include <iostream>
#include <unistd.h>  // Required for fork() and getpid()
#include <sys/types.h>

int main() {
    std::cout << "Starting program. Current PID: " << getpid() << std::endl;
    std::cout << "---------------------------------------" << std::endl;

    // The process splits into two right here
    pid_t pid = fork();

    if (pid < 0) {
        // fork failed
        std::cerr << "Fork failed!" << std::endl;
        return 1;
    } 
    else if (pid == 0) {
        // This code ONLY runs inside the Child Process
        std::cout << "[CHILD] Hello from the child process!" << std::endl;
        std::cout << "[CHILD] My PID is: " << getpid() << std::endl;
        std::cout << "[CHILD] My Parent's PID (PPID) is: " << getppid() << std::endl;
    } 
    else {
        // This code ONLY runs inside the Parent Process
        std::cout << "[PARENT] Hello from the parent process!" << std::endl;
        std::cout << "[PARENT] My PID is: " << getpid() << std::endl;
        std::cout << "[PARENT] I spawned a child with PID: " << pid << std::endl;
    }

    // Both processes will execute this line independently
    std::cout << "[PID " << getpid() << "] Program finished." << std::endl;

    return 0;
}

What does exec() do

The exec family of functions replaces the current process image with a completely new program.

While fork() creates an exact clone of your program, 
exec deletes the current program from memory and loads a brand-new executable in its place. 
The Process ID (PID) does not change, but the code, variables, and stack are entirely wiped out
and replaced by the new application.

Why fork() and exec() are used together

In Linux and macOS, you almost always see fork() and exec() used as a team to
run external programs:

1. fork() splits your program into a parent and a child.
2. exec() is called inside the child process to transform that clone into the tool
          you actually want to run (like ls, grep, or a custom Python script).

If the exec call is successful, it never returns. 
The child process finishes when the newly loaded program finishes.

Code example

#include <iostream>
#include <unistd.h>    // For fork() and execlp()
#include <sys/wait.h>  // For wait()

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        std::cerr << "Fork failed!" << std::endl;
        return 1;
    } 
    else if (pid == 0) {
        // --- Inside the Child Process ---
        std::cout << "[Child] Transforming into 'ls -l'..." << std::endl;

        // Arguments for execlp:
        // 1. Program to run ("ls")
        // 2. The name of the command (conventionally the program name)
        // 3. Flags/arguments ("-l")
        // 4. Must end with a NULL pointer to signal the end of arguments
        execlp("ls", "ls", "-l", NULL);

        // This line WILL NOT RUN if execlp is successful.
        // It only runs if the operating system couldn't find or open the program.
        std::cerr << "[Child] Exec failed!" << std::endl;
        return 1;
    } 
    else {
        // --- Inside the Parent Process ---
        std::cout << "[Parent] Waiting for child to finish running 'ls'..." << std::endl;
        
        // Wait for the child to finish so the terminal stays tidy
        wait(NULL); 
        
        std::cout << "[Parent] Child completed. Exiting safely." << std::endl;
    }

    return 0;
}

What does wait() do

The wait() function blocks the parent process
until one of its child processes finishes executing.

When a child process finishes, it doesn't vanish instantly.
It enters a "Zombie" state, saving its exit status (whether it succeeded or crashed)
so the parent can read it. The wait() system call performs two critical jobs:

1. Synchronisation: It pauses the parent process so it doesn't race ahead of the child.

2. Cleanup: It collects the child's exit status,
            allowing the operating system to completely remove the child process from memory.

If you don't use wait(), the child turns into a permanently stuck Zombie process,
wasting system resources.

Code example 

To use wait(), include the <sys/wait.h> header.
You pass an integer pointer to wait(),
which the operating system fills with information about how the child died.

#include <iostream>
#include <unistd.h>    // For fork() and sleep()
#include <sys/wait.h>  // For wait()

int main() {
    pid_t pid = fork();

    if (pid < 0) {
        std::cerr << "Fork failed!" << std::endl;
        return 1;
    } 
    else if (pid == 0) {
        // --- Inside the Child Process ---
        std::cout << "[Child] Starting a heavy task (sleeping for 3 seconds)..." << std::endl;
        sleep(3); // Simulate work
        std::cout << "[Child] Task done. Exiting with status code 42." << std::endl;
        return 42; // Exit status code sent back to parent
    } 
    else {
        // --- Inside the Parent Process ---
        std::cout << "[Parent] Waiting patiently for the child to finish..." << std::endl;
        
        int status;
        // wait() blocks the parent here until the child exits
        pid_t child_pid = wait(&status); 
        
        std::cout << "[Parent] Child with PID " << child_pid << " has finished." << std::endl;

        // Check if the child exited normally (macro provided by sys/wait.h)
        if (WIFEXITED(status)) {
            // Extract the actual return code (42)
            int exit_code = WEXITSTATUS(status);
            std::cout << "[Parent] Child exited normally with code: " << exit_code << std::endl;
        } else {
            std::cout << "[Parent] Child terminated abnormally." << std::endl;
        }
    }

    return 0;
}

The status integer returned by wait() is packed with bitwise data.
You should never read it directly; instead, use these standard macros:

WIFEXITED(status): Returns true if the child process exited normally
                   (e.g., via return or exit()).

WEXITSTATUS(status): Fetches the exact exit code returned by the child
                     (only valid if WIFEXITED was true).

WIFSIGNALED(status): Returns true if the child process was violently killed by a system signal 
                     (like a crash or a kill -9 command).
